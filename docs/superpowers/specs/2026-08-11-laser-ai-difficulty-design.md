# 激光镭射象棋三级电脑难度设计

## 目标

为人机对战增加可选择的简单、普通、困难三级电脑难度。普通电脑表现为主动进攻，困难电脑在主动进攻的同时具备更强的反击预判；所有难度均遵守现有棋规并避免明显自杀。

## 当前问题

现有 `aiChoose` 先按本回合直接击中的棋子价值排序，再仅保留前 24 个动作进行完整评估。移动或旋转镜子来搭建未来激光路线的动作通常没有即时吃子分，因此会在完整评估前被淘汰。最终局面评分还会奖励国王附近的护卫数量，进一步使电脑偏向防守。

## 方案

保留一套动作生成、激光模拟和 AI 入口，通过难度配置改变候选评分、搜索范围与随机性，不为三个难度维护三套算法。

### 简单

- 保留当前以即时结果为主的决策风格。
- 排除击中己方国王的动作。
- 不搜索对手完整回应。
- 在分数接近的动作中随机选择，使行为保留一定变化。

### 普通

- 在候选动作截取之前加入进攻局面评分。
- 奖励激光路径接近敌方国王、形成更长有效路径、击中敌方棋子和减少敌王附近防守棋子的动作。
- 保留基本的一步致命风险检查，避免下一回合被直接击杀。
- 在少量接近最优的动作中随机选择，形成明显激进的风格。

### 困难

- 对全部合理候选先进行进攻与安全综合评分，再选取高质量候选进行对手回应搜索。
- 假设人类会选择其最强回应，综合计算敌王压力、己方国王安全、双方棋子价值和激光路径质量。
- 严格淘汰存在对手一步必杀且有安全替代方案的动作。
- 只在几乎同分的动作中随机选择，整体强于普通难度。

## 评分原则

评分继续使用现有棋子价值和激光模拟结果，并补充以下信号：

- 当前激光到敌方国王的最短曼哈顿距离越小，进攻分越高。
- 有效激光路径更长、发生反射并深入敌方区域时适度加分。
- 直接消灭敌方棋子加分，消灭己方棋子扣分，击中敌方国王立即获胜。
- 对手激光逼近己方国王时扣分，但普通难度的进攻权重高于防守权重。
- 困难难度提高对手最佳回应的权重，并保留己王附近防护评分。

权重保持为文件内固定常量，不增加配置文件或第三方依赖。

## 用户界面

- `G` 状态增加 `difficulty`，默认值为 `normal`。
- 选棋阶段增加一个循环按钮，依次显示“难度：简单”“难度：普通”“难度：困难”。
- 点击按钮立即切换难度，下一次电脑回合生效。
- 重新开始或切换阵型时保留已选择的难度。
- 不新增弹窗或独立设置页面。

## 数据流

1. 玩家完成回合后进入 `aiTurn`。
2. `aiTurn` 将当前棋盘、电脑玩家编号和 `G.difficulty` 传给 `aiChoose`。
3. `aiChoose` 生成合法动作，按对应难度评分和搜索。
4. 选中的动作继续通过现有 `applyAiAction`、`fireLaser` 和 `endTurn` 流程执行。

现有棋规、动画和回合状态机不改变。

## 性能与容错

- 简单和普通难度不增加深层搜索。
- 困难难度只搜索一层对手回应，并先缩小高质量候选集合，控制微信小游戏主线程耗时。
- AI 仍保留现有异常捕获与跳过回合兜底。
- 如果没有安全动作，电脑从合法动作中选择损失最小的一步。

## 测试与验收

增加一个不依赖第三方框架的 Node 回归测试，覆盖：

- 简单难度能够返回合法动作。
- 普通难度在固定进攻局面中选择能加强敌王激光压力的动作，而不是单纯回防。
- 困难难度在固定陷阱局面中避开会导致对手下一步击杀国王的激进行动。
- 三个难度都不会在存在安全动作时主动用激光击中己方国王。
- 游戏模块仍可被 Node 解析，浏览器调试入口和微信小游戏入口使用的模块接口保持兼容。

验收时运行回归测试，并对游戏源码执行语法检查。
