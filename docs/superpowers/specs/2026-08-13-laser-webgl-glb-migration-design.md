# 镭射棋盘 WebGL / GLB 迁移设计

## 目标

保留当前原生微信小游戏工程、主界面、规则弹窗、AI、游戏流程与操作方式，仅将阵型预览和实战中的棋盘、棋子、动作特效及激光场景升级为真正的 WebGL 3D。项目直接使用用户提供的十个独立 GLB 棋子模型；不迁移到 Cocos Creator，也不引入完整 3D 游戏引擎。

当设备不支持 WebGL、模型加载失败或着色器初始化失败时，游戏自动使用当前伪 3D 棋盘，确保仍能正常游玩。

## 已有条件

- 运行平台：原生微信小游戏，基础库配置为 3.17.1。
- 当前主画布：`wx.createCanvas()` 创建的 2D Canvas。
- 当前状态源：`games/laser/laser-game.js` 内的 `G.pieces`、相机状态和动画状态。
- 模型格式：glTF 2.0 Binary（GLB），Y 轴向上、米制单位、轴心位于底部中心。
- 模型包：五种棋子、红蓝各一套，共十个独立模型；材质和颜色全部内嵌，无外部贴图、骨骼或动画。

## 总体架构

### 2D 主画布

现有主画布继续负责：

- 主界面、阵型和难度选择；
- 顶栏、按钮、状态提示；
- 规则介绍和返回确认弹窗；
- 触摸事件的统一接收和分发；
- WebGL 棋盘结果与 2D 界面的最终合成；
- WebGL 不可用时的伪 3D 棋盘绘制。

### WebGL 离屏画布

新增透明 WebGL 离屏画布，仅渲染棋盘区域：

- 10×8 立体棋盘和红、白禁区；
- GLB 棋子实例；
- 棋子选中、移动、旋转和互换动画；
- 3D 激光和命中效果；
- 相机、灯光、深度测试和透明混合。

每帧先把 WebGL 场景渲染到离屏画布，再由现有 2D 上下文绘制到主画布的棋盘区域。主界面的绘制顺序保持不变。

### 单一游戏状态源

`G.pieces` 继续是棋盘状态的唯一数据源。WebGL 渲染器只读取状态，不复制或修改走棋规则。每个渲染实例由棋子类型、阵营、格子坐标、方向、存活状态和当前动画姿态生成。

以下规则完全保留：

- 红蓝双方禁区限制；
- 双面镜与护盾、单面镜的互换规则；
- 激光炮朝向限制；
- 护盾正面阻挡；
- 单面镜单面反射；
- 双面镜双向反射；
- AI 搜索、难度和回合流程。

## WebGL 渲染器边界

使用项目内的轻量 WebGL 1 渲染器，不引入 Three.js、Cocos Runtime 或新的依赖。渲染器只实现当前模型和棋盘所需能力：

- 顶点和索引缓冲；
- 位置、法线和节点矩阵；
- 透视相机和模型矩阵；
- 方向光、环境补光及材质高光；
- 深度测试、背面处理和透明混合；
- 共享着色器和 GPU 资源缓存；
- WebGL 上下文丢失后的安全回退。

不实现实时环境反射、骨骼动画、通用 glTF 扩展、编辑器功能或运行时材质系统。

## GLB 资源与加载

十个独立模型存放于 `games/laser/models/`：

- `laser_cannon_red.glb`
- `laser_cannon_blue.glb`
- `king_red.glb`
- `king_blue.glb`
- `shield_red.glb`
- `shield_blue.glb`
- `single_mirror_red.glb`
- `single_mirror_blue.glb`
- `double_mirror_red.glb`
- `double_mirror_blue.glb`

总览 GLB 只用于资料预览，不进入正式游戏包。正式游戏复用十个独立模型的 GPU 网格，不为同类棋子的每个实例重复上传数据。

加载器只解析这批 GLB 实际使用的 glTF 2.0 内容：JSON 和 BIN 数据块、场景节点、网格 primitive、POSITION、NORMAL、索引、节点变换、PBR baseColorFactor、metallicFactor、roughnessFactor 和 doubleSided。加载完成前显示现有背景和简短加载提示。

任何文件缺失、结构越界、必要属性缺失、WebGL 编译失败或 GPU 初始化失败，都会使整套棋盘回退到旧渲染，不出现新旧棋子混合。

## 棋盘与画面

- 棋盘为 10×8 立体薄板，每格有轻微高度和深色边框。
- 红、白禁区绘制在棋盘底层，格子位置严格沿用现有规则函数。
- 模型保留内嵌红、蓝、金、银、深色和浅蓝镜面材质。
- 使用固定主方向光和环境补光表现低多边形卡通切面。
- 使用低成本接触阴影，不使用实时阴影贴图。
- 浅蓝镜面使用较强高光，但不进行实时场景反射。
- 阵型预览和实战共用同一个 WebGL 渲染器及模型缓存。

## 模型映射与方向

模型类型映射如下：

| 游戏类型 | GLB 名称前缀 |
| --- | --- |
| `laser` | `laser_cannon` |
| `king` | `king` |
| `shield` | `shield` |
| `mirror` | `single_mirror` |
| `switch` | `double_mirror` |

模型根轴心置于格子中心和棋盘上表面。棋子方向通过 Y 轴旋转表示，每个逻辑方向相差 90°。模型导入校准矩阵独立于逻辑旋转，用来把模型默认正面与游戏默认方向对齐。

### 单面镜

`single_mirror` 是竖直三棱柱。浅蓝色子节点 `Mirror_Face` 是唯一反射面；另外两块竖直侧面不是镜面。系统不根据模型外形重新定义规则，而是校准模型镜面法线，使四个逻辑方向的可见镜面方向与当前 `MIRROR_MAP` 完全一致。

校准不能只依靠一个未经验证的固定角度。测试会从 GLB 的 `Mirror_Face` 几何计算默认法线，再应用导入校准和四个逻辑旋转，逐方向对照现有激光入射/出射表。

### 双面镜

`double_mirror` 的 `Mirror_Front` 和 `Mirror_Back` 都是反射面。其视觉方向同样由模型校准矩阵和每次 90° 的逻辑旋转组成。

### 其他定向棋子

- 激光炮炮口方向必须等于发射方向。
- 护盾正面法线必须等于实际阻挡方向。
- 国王只需保持正确阵营、格子位置和统一缩放。

## 相机、交互与拾取

- 阵型选择页使用固定稳定俯视角，不响应旋转和缩放手势。
- 实战继续支持单指旋转、双指缩放，沿用现有角度和距离限制。
- WebGL 模式把触摸屏幕坐标反投影成射线，与棋盘平面求交后换算为行列。
- 只有合法的棋盘格交点进入现有点击处理流程；界面按钮和弹窗仍由 2D 层优先处理。
- 伪 3D 回退模式继续使用旧的投影与点击判定。

## 动画与激光

- 移动：模型从起点平滑抬起并落到终点，逻辑棋盘在既有提交时机更新。
- 旋转：模型绕 Y 轴旋转到新方向。
- 互换：两枚模型同时移动，并保留两处提示环。
- AI 操作：继续使用现有动作提示、忙碌锁定和提交时序。
- 激光：沿现有 `G.path` 生成 3D 发光带，包含窄亮核心和宽透明辉光；反射点与棋盘格中心、镜面朝向保持一致。
- 命中和消灭：保留现有效果时序，视觉效果完成后再进入后续状态。

动画只改变渲染姿态，不建立第二套规则状态。

## 性能与兼容

- WebGL 画布分辨率按设备像素比设置，但设置上限，避免高分辨率手机产生过大帧缓冲。
- 棋盘网格、着色器、GLB 网格和材质在一局内缓存。
- 不启用实时阴影、后处理、环境贴图、骨骼或动画系统。
- 只在状态、相机或动画变化时更新必要的实例数据。
- WebGL 初始化失败、上下文丢失或资源加载失败后，本次模块生命周期内使用旧伪 3D，不反复重试造成卡顿。
- `exit()` 必须释放 WebGL 缓冲、着色器、纹理/帧缓冲引用及相关加载回调，旧的计时器清理规则继续生效。

## 错误处理与回退

WebGL 渲染器返回明确的状态：`loading`、`ready` 或 `fallback`。错误记录包含阶段和资源名，便于微信开发者工具定位，但不把技术错误直接展示给玩家。

发生以下任一情况即进入 `fallback`：

- `webgl` 上下文不可用；
- 必需的 WebGL 1 能力不满足；
- 着色器编译或链接失败；
- 任一正式模型读取或解析失败；
- 必要网格、索引或材质数据无效；
- WebGL 上下文丢失且无法在本次模块中安全恢复。

进入回退后，棋盘、棋子、动画、激光和点击判定全部使用当前实现。

## 测试与验收

### 自动测试

- 十个 GLB 文件存在且 GLB 头、长度和 JSON/BIN 数据块有效。
- 模型类型和阵营映射完整。
- 加载器能解析这批模型的所有 primitive、法线、索引、节点和内嵌材质。
- 单面镜 `Mirror_Face` 是唯一镜面，四个方向的法线与 `MIRROR_MAP` 对应。
- 双面镜前后镜面均被识别。
- 激光炮炮口和护盾正面方向与规则方向一致。
- 红、白禁区格子渲染映射与规则一致。
- `G.pieces` 到 WebGL 实例的移动、旋转、互换和存活状态同步正确。
- WebGL 初始化、模型或着色器失败时完整切换到旧渲染。
- 现有 AI、规则、触摸锁定、返回确认和计时器清理回归测试继续通过。

### 人工验收

- 在微信开发者工具中检查阵型预览、五类模型、红白禁区和 2D 界面叠加。
- 在实战中检查选中、移动、旋转、双面镜互换、AI 动作和激光反射。
- 从四个方向分别检查单面镜入射，确认只有浅蓝镜面一侧反射。
- 检查双面镜前后两面反射。
- 检查返回、重新开始和多次进入游戏后的资源释放。
- 至少在一台真机上检查帧率、触摸拾取、清晰度和 WebGL 回退。

## 不在本次范围

- 不迁移到 Cocos Creator 工程。
- 不重写主界面、规则、AI 或游戏流程。
- 不引入通用 3D 引擎。
- 不实现真实镜面反射、动态阴影或高成本后处理。
- 不把总览模型用于正式棋盘。
- 不修改用户提供的 GLB 几何；如模型默认朝向不一致，通过导入校准矩阵处理。
